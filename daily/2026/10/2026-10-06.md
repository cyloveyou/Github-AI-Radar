# GitHub AI Radar — 2026-10-06

> 今日触发更新：Kubernetes SIG Apps 的 `agent-sandbox` 在进入 v1.0 后快速推进到 v1.0.5，并把 warm pool、持久状态、SDK runtime transport、OpenAI Agents integration、WebMCP-to-MCP bridge、OpenShell/NemoClaw 与 microVM runtime 示例集中到同一个 Kubernetes 原生执行层。相比 9 月 26 日 Radar 记录的“Sandbox / Runtime / Portable Authority”，这代表 **Agent Sandbox 正在进一步收敛为 Kubernetes 上的标准化部署单元和运行时控制面**。

## kubernetes-sigs / agent-sandbox

- **Repo:** https://github.com/kubernetes-sigs/agent-sandbox
- **Category:** Agent Sandbox / Kubernetes Runtime / Control Plane / RL Infrastructure
- **Verified snapshot:** GitHub REST 本次核验为 **4,170 Stars、547 Forks**；Apache-2.0；仓库创建于 2025-08-12，本次扫描时仍有当日提交。
- **Release:** 官方 Releases 显示 **v1.0.5** 于 2026-10-01 发布；v1.0.0 已将核心与扩展 API 统一推进到 `v1beta1`。
- **What:** 用 Kubernetes CRD 管理隔离、持久、singleton 的 Agent/RL workload；核心 `Sandbox` 加上 `SandboxClaim`、`SandboxTemplate`、`SandboxWarmPool`，将 sandbox 生命周期变成声明式基础设施。
- **Why watch:** 这不是又一个单机 sandbox。它开始承担 Agent 执行环境的调度、预热、持久化、路由、SDK 接入、可观测性与高规模控制器调优，越来越接近 Agent workload 的 Kubernetes-native control plane。

## v1.0.5 的关键变化

1. **Runtime connectivity 成熟。** TypeScript SDK 增加完整 runtime layer；Python/TypeScript 支持直接 in-cluster `sandboxd` transport，减少本地 port-forward 依赖。
2. **Durable / long-running agent。** `claim_name` + `adopt_existing` 允许重试时重新接管已有 SandboxClaim，适合长任务和可恢复 workflow。
3. **Framework integration。** 新增 OpenAI Agents SDK integration，并继续提供 Deep Agents 等适配；Agent runtime 与上层 harness 的边界正在标准化。
4. **Browser / MCP bridge。** 官方新增 WebMCP-to-MCP 示例，用 Playwright 将浏览器注册的 WebMCP tools 桥接到 Sandbox 内的 MCP。
5. **Isolation backend 多样化。** 官方示例同时覆盖 OpenShell/NemoClaw 与 `urunc` unikernel/microVM runtime，说明 Kubernetes API 与底层隔离实现正在解耦。
6. **Scale / observability。** Helm 暴露高规模 controller tuning 参数，并增加 warm-pool Prometheus gauge，说明项目目标已明显超出开发 demo。

## 与既有 Radar 的关系

9 月 26 日我们记录的是：

**Sandbox → Runtime → Portable Authority / OCI Packaging → Cloud Execution**

9 月 29 日 OpenShell 又补上：

**Runtime Policy Enforcement → Independent Oversight**

本期新增的结构是：

**Kubernetes-native Sandbox CRD → Warm Pool / Durable Claim → Runtime Transport → Framework Adapter → Multi-runtime Isolation → Agent Control Plane**

这意味着 Sandbox 不再只是“Agent 运行时里的安全功能”，而正在变成可以被调度、声明、观测、恢复和规模化管理的 **Agent workload primitive**。

## 次级信号：Sandbox API 兼容层开始出现

本轮还观察到多个项目围绕 Kubernetes Agent Sandbox / E2B-compatible API 构建兼容层和数据面。单个项目规模尚不足以分别进入主榜，但它们共同强化了一个趋势：未来竞争点可能从“谁有自己的 sandbox”转向“谁能兼容主流 Sandbox API，并在 Kubernetes / microVM / cloud runtime 之间迁移”。

因此本期只把 `kubernetes-sigs/agent-sandbox` 作为主项目写入项目库，不为较小的兼容层项目制造噪声。

## Radar 判断

这是一次**基础设施路线升级**，不是普通版本号更新。

值得继续追踪的指标：

- `agents.x-k8s.io` API 是否被更多 Agent 平台直接采用；
- E2B-compatible API 是否逐渐成为事实兼容接口；
- warm pool / snapshot / suspend-resume 是否形成长任务 Agent 的通用生命周期；
- OpenShell、Kata、gVisor、microVM/unikernel 等 isolation backend 是否在同一控制面下收敛；
- Agent harness 是否开始把 sandbox provider 当成可替换 runtime，而不是内置实现。
