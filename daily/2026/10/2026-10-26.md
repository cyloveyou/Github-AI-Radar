## 核心判断

**Agent 开发正在出现两条互补的工程路线：一是设计/多媒体 Skill 从“提示词模板”进化为“浏览器实测 + 确定性规则 + 可回归检查”；二是长期运行的 Agent 团队从共享会话走向“每席位身份、权限、预算、切换和可审计控制”。** 模型网关也不再只做转发，而尝试把身份预算与真实流量反馈接入路由优化。Star 热度不能证明设计质量、隔离强度或路由成本优势。

- **评价边界：** 这是“设计生成 + 可检查验收”的工具链，而非已经证实审美优越的模型。README 的 v2 不等于本次核验到一个正式 GitHub Release；主题数量、照片素材数量均为官方项目说明，真实可访问性仍需浏览器/人工检查。

## 4. OpenRig v0.7.1–0.7.2：每席位授权、账户与 Harness 受控切换（重要更新）

- **官方仓库：** https://github.com/mvschwarz/openrig ，GitHub REST **8,192 Stars / 672 Forks**，Apache-2.0。此前 10 月 25 日已报道 v0.7.0 的人工 Quiet Hours 和局部恢复；本次为不同的控制面变化。
- **官方 Release：** `v0.7.1` 于 **2026-10-25 07:29 UTC** 发布，新增每个 seat 的自动输入/终端干预权限、TUI 人工审批 Feed、Slack 紧急消息订阅；`v0.7.2` 于 **2026-10-25 22:18 UTC** 发布，支持每席位 `CLAUDE_CONFIG_DIR` / `CODEX_HOME`、切换订阅账户，以及在 Claude Code 与 Codex 间保留队列/地址并执行确认式交接。
- **关键边界：** v0.7.1 既有 seat 仍保留旧的 full-control 策略，不能假设升级后自动最小权限；v0.7.2 在 Linux 上改变会话 D-Bus 默认访问，升级要重启 daemon 并迁移数据库；回退旧版本可能丢失新的 Claude 工具规则约束。必须先核查权限、备份和恢复测试。
- **意义：** 不再只解决“多个 Agent 同时运行”，而是把 **身份、订阅、权限、运行时替换、任务交接** 明确为独立控制对象。跨运行时连续性是官方实现描述，尚未独立验证长任务中断恢复率。

## 5. Ruflo v3.63.0：有预算和签名验证门槛的 Managed Agent Control Plane（重要更新）

- **官方仓库：** https://github.com/ruvnet/ruflo ，GitHub REST **79,279 Stars / 9,305 Forks**，MIT。官方 `v3.63.0` 发布于 **2026-10-25 03:15 UTC**。
- 新增四项 MCP 接口：`managed_agent_capabilities`、`managed_agent_control`、`managed_agent_learning`、`managed_agent_interrupt`。动态工作流必须设置 `budgetCents`，管理控制需主机显式启用并将会话加入白名单；学习结果要求签名和验证公钥，未签名记录隔离，不自动修改路由。
- **风险提示必须保留：** Release 明确声明**尚未使用真实 Anthropic Managed Agents beta 执行器密钥做过线上测试**；签名检查与被执行内容只有部分绑定，锁文件可能残留，error 状态会话无法控制。所谓“verified advisory learning”不能被当成已证实的生产级安全或模型性能改进。
- **路线变化：** Agent Runtime 的外部控制面开始把 **显式授权、预算、验证证据、停止/中断** 放到一套 MCP 契约内，与 OpenRig 的席位级权限互补。
