## 核心判断

本期的共同变化是 **Agent 的安全默认值、事件触发、可查询结构、记忆决策与模型网关访问边界正在工程化**。这些方向可分别通过最小权限测试、事件漏报率、图谱边保真率、技能选择质量与网关拒绝测试验证；热榜 Stars 不代表安全性、质量或真实用户数量。

## 1. Ruflo v3.57.0：Coding Agent 初始化转向显式授权

- 官方仓库：https://github.com/ruvnet/ruflo ；正式发布：https://github.com/ruvnet/ruflo/releases/tag/v3.57.0 （2026-10-17 22:38 UTC）。
- GitHub REST：**76,501 Stars / 9,046 Forks**，MIT；Trending Daily 显示 **502 stars today**（榜单瞬时口径）。
- `ruflo init` 生成的 Codex 配置改为 `sandbox_mode=workspace-write`、`approval_policy=on-request`、`web_search=cached`；高权限模式必须显式指定 `--codex-trust full`。已有配置不会被自动覆盖。
- 无 `MCP_AUTH_TOKEN` 时，回环 MCP bridge 要求 loopback `Host`，且 `Origin` 必须是 loopback 或白名单，以降低网页跨源调用本机工具的风险。Policy ledger 还引入独立归档锚点校验。
- **区别于**先前 Strands Box/Substrate 的沙箱和运行时隔离：这里是多 Harness 工具在「初始化默认值 + 本机 MCP 入口 + 策略账本」三个边界同时收紧。安全性仍需独立攻防复核。

## 2. Rakazo：Automation 从定时唤醒转向事件指纹触发

- 官方仓库：https://github.com/elie222/rakazo ；一手合并提交：https://github.com/elie222/rakazo/commit/4429327e918e555ec91b43eb5c974a81b72cc8c4 （2026-10-18 23:19 UTC，**主分支提交，非正式 Release**）。
- GitHub REST：**4,589 Stars / 832 Forks**，Apache-2.0；Trending Weekly 显示 **808 stars this week**。
- 新增 `RoutineWatch`：监控文件/目录、命令输出或集成工具结果，先以低成本指纹比对发现变化，再启动模型任务；首次检查建立基线。默认检查间隔为 15 分钟，可设置静默或报告「无变化」。
- 检查路径不存在、命令非零退出或工具错误时，暂停该 Watch 并在会话中说明原因，避免静默重复失败。Watch 与定时 Schedule 互斥。
- **技术路线**：`scheduled LLM polling → deterministic change detection → conditional agent execution`。这是提交级新能力，尚无独立漏报率、误触发率与长期稳定性测试。

- 官方仓库：https://github.com/Graphify-Labs/graphify ；正式发布：https://github.com/Graphify-Labs/graphify/releases/tag/v0.9.92 （2026-10-16 17:57 UTC）。

- 与 PageIndex 的 PDF 布局树、Context Mode 的工具输出检索不同，本项目强调 **确定性 AST → 跨语言关系图 → MCP 查询**。升级会改变 AST 缓存 Schema，首次重建需重新抽取；图谱正确率与跨版本一致性需实测。

## 4. TencentDB Agent Memory v2.0.3-beta.1：团队记忆加入可插拔决策层

- 官方仓库：https://github.com/TencentCloud/TencentDB-Agent-Memory ；发布：https://github.com/TencentCloud/TencentDB-Agent-Memory/releases/tag/v2.0.3-beta.1 （2026-10-13 10:43 UTC；**版本名称为 beta，GitHub release 元数据未标记 prerelease**）。
- GitHub REST：**29,569 Stars / 2,952 Forks**，GitHub API 许可证标记 `NOASSERTION`；Trending Weekly 显示 **1,631 stars this week**。
- 新增可插拔决策服务，将 Skill 选择和 Memory L3 更新判定统一到接口；启用后可按需选择技能而不是每轮注入完整 Skill 目录；会话轨迹可写入 MemoryCore `/v3/session/add`。
- 新能力默认关闭，旧配置维持原行为；决策服务失败不阻断对话及记忆写入。技术重点是 **记忆资产治理 → 选择/更新决策 → 运行时观测**，需要评估误选 Skill、漏更新记忆和故障回退效果。

## 5. Mozilla Otari v0.28.0：LLM Gateway 转向供应商白名单

- 官方仓库：https://github.com/mozilla-ai/otari ；正式发布：https://github.com/mozilla-ai/otari/releases/tag/v0.28.0 （2026-10-16 19:09 UTC）。
- GitHub REST：**659 Stars / 83 Forks**，Apache-2.0；Trending Daily 显示 **46 stars today**。本项由安全架构变化触发，**不是**由绝对热度触发。
- **Breaking change**：不再仅凭环境变量自动启用模型供应商，必须在配置或管理界面显式声明；未声明的请求返回 `424 provider_not_configured`。无密钥的本地 Ollama/vLLM 也需要配置条目。
- 这一变化把模型访问从「凭据存在即可能被使用」调整为 **显式配置的供应商边界**，与 Ruflo 的工具执行最小权限互补。升级需检查兼容性与已有配置。
