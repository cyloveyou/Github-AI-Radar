## 1. Substrate v0.6.0：Sandbox Runtime 的资源、镜像与身份边界收紧

- 官方仓库：https://github.com/agent-substrate/substrate ；正式发布：https://github.com/agent-substrate/substrate/releases/tag/v0.6.0 （**2026-10-22 17:25 UTC**）。本期 REST **5,733 Stars / 620 Forks**，Apache-2.0。
- **Breaking Changes：** Actor 创建要求明确 CPU、内存限制；资源和卷容量改用整数（`cpuMillicores`、`memoryBytes`、`capacityBytes`）。移除 PauseActor RPC，重命名 worker 组件，调整 gVisor SandboxConfig。
- **完整性与隔离：** 镜像层进入缓存池前按 diffID 校验；拒绝旧版缓存布局；每个 Actor 使用独立快照目录；GKE 微虚拟机资产与快照桶分离，GCS 快照传输使用专用服务账户；网络入口增加认证模式与 SPIFFE 身份检查。
- **技术意义：** 从 10 月 17 日 v0.5.0 的“可版本化配置、快照保真度、Actor JWT”推进为 **资源上限强制声明 → 镜像内容校验 → Actor 级快照/凭据隔离 → 网络身份验证**，是实际不兼容升级。
- **限制：** 官方实现声明未经独立资源耗尽、恶意镜像、快照跨租户访问或故障注入测试。升级须评估 RPC/Proto 兼容性。

## 2. Graphicle v0.1.4：本地代码图谱与 Agent Memory 合并为一个 Rust 进程

- 官方仓库：https://github.com/Graphicle-AI/graphicle ；发布：https://github.com/Graphicle-AI/graphicle/releases/tag/v0.1.4 （**2026-10-22 01:29 UTC**）。创建于 **2026-10-14**，本期 REST **342 Stars / 27 Forks**，Apache-2.0。
- 将代码图、项目文档/决策、历史 Agent 会话和 MCP 检索统一到一个 Rust 程序与本地 SQLite 文件；`graphicle ask` 返回带文件名和行号的证据片段，支持 Token 预算；Agent 提议写入的长期记忆需人工批准。
- 官方提供从 Graphify 迁移的文档；两者是不同项目，**不应误写为 Graphify 的官方升级版**。Graphicle 声称在 13 个代码库上部分操作快 **3.0–22.7 倍**，为作者自报、尚未独立复现。
- v0.1.4 改善系统/企业 CA 信任与 TLS 诊断。技术路线是 **可引用的代码证据 + 可审阅的项目记忆 + 本地轻量 MCP**，不同于此前 Graphify 的 AST 图谱结构修复。
- **限制：** 0.1.x 阶段；需验证跨语言边准确率、记忆误写、增量索引和与 Graphify 的同机对照。

## 3. SCP：跨机器、多 Harness Agent 的消息协议层

- 官方仓库：https://github.com/scphq/scp ；协议：https://scp.dev/spec ；发布：https://github.com/scphq/scp/releases/tag/%40scp-dev/core%400.10.1 （**2026-10-22 20:45 UTC**）。创建于 **2026-10-18**，本期 REST **69 Stars / 1 Fork**，Apache-2.0。
- Swarm Communication Protocol 使用 Harness Hooks/MCP、每机 Local Broker、WebSocket Bridge 和可自托管 Relay；面向 Claude Code、Codex、OpenCode、pi 等不同 Harness。
- README 描述工具调用后、提示前、停止时的 turn-level 投递，以及休眠会话被消息唤醒、跨组织双方同意和可选 judge 审核。仓库提供规范、核心类型、Broker、MCP 和实验性无中心 Mesh；v0.10.1 主要优化 Broker 查询范围。
- **技术意义：** 与 10 月 21 日 Reason Network 的 P2P 消息/人工审批不同，SCP 进一步尝试规定 **协议、交付时机和 Harness 适配约定**，但尚不能断言已成为互操作标准。
- **限制：** 需要实测重复投递、断网重连、休眠唤醒权限、跨组织撤权和消息完整性；长期恢复是官方设计主张。

## 4. axuse：Computer Use 从截图循环转向结构化可访问性接口

- 官方仓库：https://github.com/ctoldigital/axuse 。创建于 **2026-10-14**，本期 REST **279 Stars / 16 Forks**；暂无正式 Release，License API 返回 `NOASSERTION`，不推断 SPDX 许可证。
- 单一 MCP Server 接入 Codex、Claude Code、OpenCode 等 Harness；通过 CDP、DOM/Accessibility Tree、稳定元素引用和差量快照执行浏览器操作，而非持续截图推理。Node.js 22+，README 称无 npm 运行依赖。
- README 描述 Windows 桌面驱动、macOS 显式开启并需 TCC 权限、Linux X11/XWayland 桌面控制；无桌面服务器可启动私有 Xvfb；可配置 Browser/Tab 上限。
- **技术意义：** 对比 10 月 21 日 OpenGCUA 的“GUI + API/Shell 混合执行”，axuse 把 **结构化 UI 语义与跨 Harness MCP 接口**放在首位，可检验截图式 Agent 的 Token、延迟与定位误差。
- **限制：** 大规模生产验证属作者声明；应审计浏览器扩展桥接授权、网页提示注入、桌面权限和 CDP 会话隔离。

- 官方仓库：https://github.com/feder-cr/git-ai ；发布：https://github.com/feder-cr/git-ai/releases/tag/v0.3.1 （**2026-10-22 22:32 UTC**）。本期 REST **966 Stars / 92 Forks**，License API 为 `NOASSERTION`。

- **技术意义：** 10 月 21 日 v0.3.0 记录“并发落地 + exact-tree 验证”；本次补充 **剩余错误率和分支引用正确性修复**，说明“测试通过”并不等于语义冲突全部解决。
