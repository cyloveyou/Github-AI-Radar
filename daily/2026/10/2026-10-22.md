## 1. Vercel durable-harness：Coding Agent 的可恢复工作流

- 官方仓库：https://github.com/vercel-labs/durable-harness ；官方文档：https://vercel.com/docs/agent-harnesses 。创建于 **2026-10-16**，本期 REST **143 Stars / 8 Forks**，Apache-2.0。**无 GitHub 正式 Release**；README 明确标为实验性 0.0.x。
- 支持 Pi、OpenCode、libfx fx、Claude Code、Codex。基于 Workflow SDK World 将 Agent session 变为 durable workflow：对话、执行中的 turn、模型调用和工具调用都记入事件日志。官方设计目标是崩溃后在另一台机器恢复执行，避免不可重复的工具调用被重复执行。
- 模型选择的命令和文件操作运行在虚拟工作区或独立 Vercel Sandbox，而不是驱动会话的主机；Claude Code/Codex 使用各自 session 的 Sandbox。支持本地 World、Vercel 托管和 Postgres World。
- **技术意义：** 将工具副作用与事件日志关联，形成 Agent durable execution substrate。区别于此前 OpenRig 的会话恢复和 Substrate 的 Sandbox 快照：强调**工作流事件重放 + 工具执行幂等性边界**。
- **限制：** 恢复语义与隔离机制来自项目设计声明，未独立做故障注入、跨机恢复或 exactly-once 测试；0.0.x API 可能变化。

## 2. browser-use/rl-env-use：从真实网页自动构造可核验 RL 环境

- 官方仓库：https://github.com/browser-use/rl-env-use 。创建于 **2026-10-21**，本期 REST **102 Stars / 4 Forks**，MIT；**没有正式 GitHub Release**，属于新开源项目。
- Browser Use Agent 从网页挖掘真实案例（如临床试验注册资料与后续结果），程序化计算 gold answer；拒绝泄漏答案、模糊问题和模型轻易解出的任务，再用 train/test 分离、噪声下限和成对置信区间 hillclimb 模型提示词。输出可用于 RL 的数据集或代码式 Env。
- 仓库提供 trial-forecast 示例：作者称 29 项试验形成 35 个预测任务，构建花费 **72 美元（Browser Use 部分 17 美元）**；Qwen 35B-A3B 分数由 0.53 到 0.78。**均为作者自报，未独立复现**；0.75 的“恒报 50%”基线提示大部分提升来自校准，不可误写为事实检索能力大幅跃升。
- **技术意义：** Browser Agent 从网页执行工具进一步进入 **真实案例挖掘 → 自动验题 → 训练/评测环境生成**。与昨日 OpenGCUA 的 Computer Use 执行层互补。
- **限制：** 需警惕时间泄漏、答案计算错误、领域数据偏差；使用 Browser Use/OpenRouter API。

## 3. UCLA OpenVLHarness：可寻址的视觉证据记忆

- 官方仓库：https://github.com/uclanlp/OpenVLHarness ；技术报告：https://arxiv.org/abs/2610.26860 ；主页：https://openvlharness.github.io/ 。创建于 **2026-10-15**，本期 REST **165 Stars / 3 Forks**，MIT；**无正式 GitHub Release**，属于科研代码公开。
- 不微调骨干模型，组合 visual grounding、OCR、深度估计、相机轨迹、局部放大、文本/图像搜索、网页访问和 Python Coding Agent 九类能力。框、mask、深度图、图片和网页引用留在同一问题的可寻址记忆中；后续工具可引用此前结果，Python Agent 在独立上下文中做数值计算。
- 官方 README 报告跨 22 个 benchmark、七种骨干模型平均提高 **9.7–12.6 分**，**仅为作者自报结果，非独立复现**；模型调用成本、工具后端和真实场景泛化仍需评估。
- **技术意义：** Memory 从纯文本摘要延伸为**带坐标、mask、数值数组和证据来源的多模态工作区**。区别于昨日 Harness² 的通用 Harness 优化，OpenVLHarness 重点解决视觉推理中间证据的跨步骤复用。

## 4. claude-mem v15.0.0 / v15.0.1：三段式 Smart Recall

- 官方仓库：https://github.com/thedotmack/claude-mem ；正式发布：https://github.com/thedotmack/claude-mem/releases/tag/v15.0.0 （**2026-10-20 21:52 UTC**）与 https://github.com/thedotmack/claude-mem/releases/tag/v15.0.1 （**2026-10-20 22:40 UTC**）。本期 REST **102,153 Stars / 8,999 Forks**，Apache-2.0。
- **v15 重大变化：** 默认 Smart Recall 采用“搜索紧凑索引 → 查看命中结果的上下文时间线 → 仅获取选中的详细观察”三段式，由 Agent 判断相关性；旧 mem_search guided/auto 和 flash_search 迁移为 mem-search Skill，保留 dumb_search 作为浅层确定性检索。升级需要刷新 MCP 客户端工具目录。
- **v15.0.1 正确性修复：** 合并项目别名下的搜索结果、时间线和详情使用一致的 project scope，避免第一步找到的观察在后续步骤错误返回 not found；发布说明称包含 HTTP/SQLite 回归测试。
- **技术意义：** 与 10 月 14 日记录的“子 Agent 压缩后恢复记忆”不同，本次是**检索协议与信息披露粒度变化**：先定位、再展开、最后按需取证。节省量和准确率仍需独立测量。
