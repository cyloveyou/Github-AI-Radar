# GitHub AI Radar — 2026-10-03

> 今日触发更新：Decision Model 从 9 月 24 日 Radar 记录的 kev / laya 小型实验信号，升级为更明确的 Agent **System-1 / Decision Layer** 路线。Strands Labs 在 9 月 29 日公开 strands-decider；Cloudflare 又在 10 月 1 日发布 Clef / Clef-flash 并开源模型权重。两条独立路线同时把“高频结构化判断从大型生成模型中拆出”推向可复现、可部署的 Agent 基础设施，因此属于显著技术路线变化。

## strands-labs / strands-decider

- **Repo:** https://github.com/strands-labs/strands-decider
- **Category:** Decision Model / System-1 Model / Agent Routing / Guardrails
- **Verified snapshot:** GitHub REST 本次核验为 **293 Stars、44 Forks**；Apache-2.0；仓库创建于 2026-09-29，扫描时仍有最新提交。
- **What:** 一个面向 agentic workflow 的小型快速 decision model。与生成式 LLM 不同，它直接在候选项之间选择或给出评分，并返回 calibrated confidence。
- **Architecture:** 官方 README 说明首个公开模型约 1.9B 参数，基于 Qwen3.5-2B-Base torso，移除 language-modeling head，替换为约百万参数的 pointer head；一次 forward pass 完成判断，不走生成/解码循环。
- **Agent use cases:** model routing、tool selection、tool argument checking、triage、guardrails、evaluation，以及“大模型做复杂判断 + decider 做重复判断”的 hybrid agent。
- **Why watch:** 这不是“再做一个更小的 LLM”，而是在 Agent loop 中形成独立的低延迟判断层。

## Cloudflare Clef / Clef-flash — 厂商级二次确认

Cloudflare 2026-10-01 官方发布 Clef 与 Clef-flash，并将模型权重以 Apache-2.0 开源到 Hugging Face。它们同样面向 bounded structured decision，而不是开放式文本生成。

更值得关注的是 Cloudflare 把 decision model 与完整 Agent 基础设施串起来：

- AI Gateway 收集真实请求/响应作为数据；
- Workers AI 承担推理和 rollout；
- Containers 作为 RL sandbox；
- Trainer 更新权重；
- Workers AI / BYO Model 重新部署微调后的 decision model。

这意味着 decision layer 已开始从单个模型实验进入“数据采集 → RL/微调 → sandbox → 部署”的工程闭环。

## 与 2026-09-24 Radar 的关系

9 月 24 日记录 kev / laya 时，Radar 的判断还是：

**Agent 的每一步不一定都需要大型生成模型。**

本期证据让这条路线更清晰：

**Input / State → System-1 Decision Model → Routing / Tool Selection / Guardrail / Scoring → 复杂任务再升级到 LLM → Skills → Sandbox / Runtime**

关键变化有三点：

1. **从“small model”变成专门的 decision architecture**：输出空间被约束为选择、评分和置信度，而不是自由生成；
2. **从 demo 变成可复现工程**：Strands Decider 公开训练、评测和 serving 路径；
3. **从模型变成平台闭环**：Cloudflare 把 decision model 与 AI Gateway、RL sandbox、trainer 和部署基础设施连接起来。

## 今日判断

Agent 基础设施正在同时沿两条互补主线成熟：

```text
Control path:  Harness → Sandbox → Runtime Policy → External Enforcement
Decision path: LLM-only loop → Small Router → System-1 Decision Model → Hybrid Agent
```

前者解决“Agent 能做什么、在哪里执行”；后者解决“Agent 每一步是否真的需要调用昂贵的大模型”。二者结合后，Agent runtime 会越来越像一个具有权限边界、快速决策层和复杂推理层的分层系统。

## 对科研工作流的直接启发

1. 批量数据下载、文件分类、任务路由、是否重试、是否升级人工检查等高频判断，可优先考虑轻量 decision layer；
2. GNSS / 电离层自动化流程中，大模型可以保留给异常解释、方法选择和复杂诊断，而把格式检查、质量门限、数据源选择等结构化决策下沉；
3. decision confidence 可作为自动化流程中的升级阈值：高置信度自动执行，低置信度交给大型模型或人工；
4. 后续重点跟踪 Decision Model 是否形成稳定 benchmark、跨 harness API，以及与 policy engine / sandbox runtime 的直接集成。
