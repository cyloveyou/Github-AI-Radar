## 1. OpenRig v0.6.10 — 多 Harness Agent 团队的状态与交付语义

- **官方仓库：** https://github.com/mvschwarz/openrig
- **官方发布：** https://github.com/mvschwarz/openrig/releases/tag/v0.6.10 （2026-10-12 07:01:52 UTC）。
- **GitHub REST 快照：** 7,247 Stars / 550 Forks；Apache-2.0；创建于 2026-04-01。GitHub Trending Weekly 本次页面显示 **2,056 stars this week**，属于页面显示值，不能替代同口径历史快照计算。
- **核心设计：** 官方概括为“A harness wraps a model. A rig wraps your harnesses.” 通过 YAML 声明团队角色、座席、任务所有权和共享上下文，让 Claude Code、Codex 等不同 Coding Agent 组成持续运行的团队；daemon、SQLite、tmux/TUI 提供运行和恢复机制。
- **重要变化：** 10 月 11 日 v0.6.9 改善跨主机消息与 Slack 交互；当跨主机发送的远端执行结果不明时明确返回 **Delivery UNCONFIRMED**，提示检查后再重发，避免错误地把超时等同失败。10 月 12 日 v0.6.10 继续修复 Claude 会话 ID 变化后的恢复、Codex launcher 背后座席的消息交付、队列查询性能，以及部分恢复却误报完全恢复的问题。
- **为什么值得收录：** 之前 Paperclip 侧重任务控制面、持久工作区与人工接管，Kubernetes agent-sandbox 侧重工作负载隔离和调度；OpenRig 进一步展示 **multi-harness seat ownership → durable session identity → cross-host delivery uncertainty → recoverable team runtime**。对长期 Coding Agent 项目而言，可靠的状态语义比多开几个终端更关键。
- **边界：** 需 Node.js 22/24、tmux；原生 Windows 不支持，WSL2 自动化测试尚未覆盖。安装会修改部分宿主设置，权限策略需人工审阅；没有独立可靠性评测。

## 2. Context Mode — 上下文不只是压缩，而是工具数据流路由

- **官方仓库：** https://github.com/mksglu/context-mode
- **GitHub REST 快照：** 27,280 Stars / 1,944 Forks；创建于 2026-02-23；GitHub REST License 标为 NOASSERTION，项目 README 自称 ELv2，应以 LICENSE 原文判断具体使用约束。
- **热度：** GitHub Trending Daily 本次显示 **246 stars today**。项目并非新创建，官方最新 Release 仍是 2026-06-29 的 v1.0.169；本期记录其未收录的技术路线，而不是声称最近发布新版本。
- **核心设计：** 将原始工具输出保留在沙箱/索引层，模型只获得程序计算或检索后的小结果；SQLite 记录编辑、Git 操作、错误、决策等会话事件，并通过 FTS5/BM25 在压缩后检索相关状态。项目声称通过 MCP 和 hooks 适配 17 种客户端，部分平台可自动引导工具调用路由。
- **技术判断：** 从“把长文本压短”变为 **tool output → sandboxed processing → indexed state → selective retrieval → model context**。这与 10 月 9 日 Hindsight 的事实/指导分离互补：Context Mode 重点在上下文预算和工具输出入口，Hindsight 重点在长期记忆的语义治理。
- **边界：** README 的“315 KB→5.4 KB / 98% reduction”是项目示例，不是独立测评；应检查索引遗漏、检索召回、hook 兼容性和本地数据生命周期。README 展示的企业徽标不能视作经核实的客户采用证明。

## 3. text-to-cad v0.7.21 — Agent 成果物从示意图进入 CAD/制造工作流

- **官方仓库：** https://github.com/earthtojake/text-to-cad
- **官方发布：** https://github.com/earthtojake/text-to-cad/releases/tag/v0.7.21 （2026-10-11 15:14:48 UTC）。
- **GitHub REST 快照：** 19,637 Stars / 1,932 Forks；MIT；GitHub Trending Weekly 显示 **2,441 stars this week**。
- **核心设计：** Agent Skill + 本地 CAD/MCP 服务，通过 build123d/Open CASCADE 等构建 3D 模型，导出 STEP、GLB、STL、3MF，配套工程图、设计可制造性检查（DFM）和 3D 打印/钣金/CNC 服务连接。可接入 Claude Code、Codex、Cursor、Gemini 等宿主。
- **与此前项目区别：** 10 月 12 日 Anatomy 是交互式技术示意图，10 月 8 日 diagram-design 侧重图形/数据约束；text-to-cad 则把 Agent 生成结果推进到 **parametric CAD → engineering formats → DFM checks → fabrication handoff**，可用于真实工程设计验证，而非仅仅视觉呈现。
- **版本说明与局限：** 0.7.21 主要修复 STEP 尾部崩溃、浏览器首帧竞态等问题，不应误写为重大发布。DFM 检查不等于结构强度、加工公差或实际安全性的独立验证；安装默认收集匿名使用统计与崩溃报告，README 提供关闭方式。

## 本期趋势与去重结论

1. **Harness → Rig / Team Runtime：** 多模型/多客户端协作开始需要稳定的角色地址、任务所有权、会话恢复和不确定交付状态；不只是多 Agent 对话。
2. **Memory → Context Data Plane：** 关键不仅是存储多少上下文，还包括原始工具输出是否进入模型、哪些事件索引化、压缩后如何恢复。
3. **Visual Artifact → Engineering Artifact：** 从 SVG/HTML 可视化走向 CAD/STEP、DFM 和制造交接；形式检查不能替代工程验收。

这三条分别补充既有 Agent Infrastructure、Context & Memory、Domain Toolchains 趋势，不把 10 月 12 日已经报道的 REA 6.4.0 或 Anatomy 当作新项目。
