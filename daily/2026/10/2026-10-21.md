# GitHub AI Radar — 2026-10-21

本期经过 GitHub Trending、近期创建项目与官方 GitHub REST/README/Release 核验，并与截至 2026-10-20 的日报、`data/projects.json`、`data/snapshots` 和趋势文档去重，发现五项有独立技术意义的新增项目/正式发布：Harness²、gitai、OpenGCUA、Reason Network、earshot。

## 核心判断

**Agent 生态正在从“把模型放进工具循环”，走向“优化 Harness、支持高并发协作、跨界面操作、团队间传递状态，并让生成的多模态成果可被程序化检查”。** 这五项并非同类工具重复上榜，分别代表自优化、版本控制、Computer Use、Agent 通信与音频反馈五个不同的技术层。

## 1. Google Research Harness²：递归优化 Agent Harness

- 官方仓库：https://github.com/google-research/harness2 ；论文：https://arxiv.org/abs/2610.14224 。仓库创建于 **2026-10-06**，本次 GitHub REST 核验 **15,318 Stars / 1,414 Forks**，Apache-2.0。**没有核验到正式 GitHub Release**，不是“今日发布新版本”。
- 将模型周围的 system prompt、guardrails、memory、tool guidance、subagents、skills、scripts 和 plugins 视为可优化对象。任务内采用 **Propose–Probe–Compose**，对候选 Harness 在同一任务上做对比试探，再组合改进；任务间将有证据的经验写入持久 improvement harness。模型权重不变。
- 官方报告在 WorkBuddy-Bench、JobBench、LAB 上观察到部分模型与配置的分数提升（最高分别约 **11.5、4.5、11.8** 分/百分点，指标口径因 benchmark 不同而不同）；这些是**作者自报实验结果**，不是独立复现。支持 OpenCode/Codex executor 和并行/顺序递归。
- **安全限制必须强调：** README 明示 executor 默认网络不受限制，Codex 运行时禁用 sandbox；在公开评测或含敏感数据的真实项目上运行前必须另行限制网络与执行权限，避免 benchmark 答案泄漏。
- 与此前的 autoharness“在线生成技能”不同，这一工作系统性地优化整个 Harness 的八类组件，并把任务内对比证据带到跨任务改进。

## 2. gitai v0.3.0：为多 Coding Agent 并发重新设计版本控制

- 官方仓库：https://github.com/feder-cr/git-ai ；正式发布：https://github.com/feder-cr/git-ai/releases/tag/v0.3.0 （**2026-10-20 12:42 UTC**）。创建于 **2026-10-15**，REST **1,267 Stars / 122 Forks**。GitHub License SPDX 返回 `NOASSERTION`，README 声称 MIT；以仓库实际许可文件为准。
- 受 Anthropic 公开的 Scion 设计启发，项目明确声明是**独立实现、非 Anthropic 官方产品**。把稀疏对象读取、服务端历史/搜索、compare-and-swap 落地、changeset log、审查与 per-agent 身份整合进 Go/Git 服务端。
- **v0.3.0 的实质增量：** 存储 checkpoint、GC、后台 hydration；冲突文件返回三方内容与可审计的 resolution package。模型生成的冲突解决方案只有在针对“即将落地的精确树”配置的 `verify.command` 通过时才能自动落地，否则只作为 proposal 返回给 Agent。规则解法与模型解法有不同信任边界。
- **破坏性升级：** v0.2.x 节点不能与迁移后的存储数据库混用，且没有直接 downgrade 路径。发布说明要求升级所有节点并保留数据库与对象存储备份；模型生成代码的验证命令应在无网络、只读、无凭据的容器中执行。
- 官方自测 50 Agent 并发场景、延迟和吞吐改进仅能说明作者的实验设置；多机部署、真实断电、云对象存储仍列为未验证。趋势重点是 **Agent 并发写入 → 精确树验证 → 可追溯变更集 → 受控合并**。

## 3. OpenGCUA v0.1.2：GUI + 代码执行 + 跨设备的通用 Computer Use

- 官方仓库：https://github.com/Tongyi-MAI/OpenGCUA ；发布：https://github.com/Tongyi-MAI/OpenGCUA/releases/tag/v0.1.2 （**2026-10-19 11:16 UTC**）；技术报告：https://arxiv.org/abs/2610.22200 。创建于 **2026-10-15**，REST **339 Stars / 25 Forks**，Apache-2.0。
- 公开的是**研究预览**：OSWorld 集成示例、八种模型的评测轨迹、初步 macOS 原生 Harness 和跨设备 SDK。不是已完成、可在所有平台运行的“全栈通用 Agent”。
- 核心路线从截图点击升级为：**Accessibility Tree / App API / Shell / GUI** 联合选择，并将多步 GUI 动作编写成包含循环和条件的代码，减少重复模型调用；同时探索后台窗口与真实设备交互。
- 官方声称在 OSWorld-v2 离线评测上平均 partial score 从 45.3 到 64.9、步数减少 53%，但**尚无独立复现**，且 partial score 不能等同于完整任务成功率。
- v0.1.2 发布说明确认 Apple Silicon macOS 14+ App、部分 macOS/Linux Python SDK wheel 和校验和。需要继续验证权限审批、真实设备隐私与模型迁移效果。与昨日 ESP32 iPhone Agent 的物理 HID 路线互补，而非同一种实现。

## 4. Reason Network v0.12.1：跨人、跨设备、跨 Harness 的 Agent 通信

- 官方仓库：https://github.com/reason-machines/reason-network ；发布：https://github.com/reason-machines/reason-network/releases/tag/v0.12.1 （**2026-10-20 23:35 UTC**）。创建于 **2026-10-16**，REST **686 Stars / 53 Forks**，Apache-2.0/MIT 双许可证文件。
- 每台电脑一个 daemon，利用 iroh 连接 P2P；Agent 可以通过 MCP 发现队友当前会话（仓库、分支、忙闲）、发送消息或小文本文件，遇到授权事项用 `ask_user` 让真人确认。官方称直接链路失败时中继只接触加密流量。
- v0.12.1 重点是 Windows relay 测试、会话入网引导、消息转义控制与 presence 解析加固；不是新提出的协议标准。跨网络连通性、离线队列、成员撤销、消息来源真实性及敏感代码传输仍需独立验证。
- 区别于 OpenRig 的多 Agent 任务编排与会话恢复：Reason Network 更接近**跨团队/跨机器的通信与身份层**，不能把“支持消息传递”误写为具备完整的任务 Control Plane。

## 5. earshot v0.2.0：给 Coding Agent 增加可量化的音频反馈回路

- 官方仓库：https://github.com/Leonxlnx/earshot ；发布：https://github.com/Leonxlnx/earshot/releases/tag/v0.2.0 （**2026-10-16 22:38 UTC**）。创建于 **2026-10-15**，REST **1,945 Stars / 111 Forks**，MIT。
- CPU 本地运行的 CLI/Python API/MCP，向 Agent 提供音频描述、文本匹配、片段定位、响度/频谱测量、时间线与视频同步检查；`forge` 用可编辑 DSP 配方合成声音，再按参考音频和客观测量指标迭代，`fit` 将录音拟合成可再渲染的 Python 配方。
- 重点不是“生成音乐”，而是 **Agent 生成视频/交互内容 → 听觉检查 → 定位缺陷 → 代码合成/修正 → 复验**。它与此前 HyperFrames 视频成果物形成可验证的多模态生产链。
- **版本边界：** README 已提到 0.3 功能，但 GitHub `releases/latest` 仍是 v0.2.0；不要把 README 的更新等同于正式 0.3 发布。作者的 CLAP 相似度、盲测和专业影片评分属于自报，未独立复核。
