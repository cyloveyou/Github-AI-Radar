## 核心判断

**Agent 的可验证执行正在出现两条更细的工程路径：** 其一，科研领域把并行探索、外部形式化验证与权限隔离整合进专用 Harness；其二，跨 Agent 生产环境开始为版本控制、休眠唤醒和可移交成果物建立明确的状态/身份契约。同时，训练过程本身开始成为 Coding Agent 的动态可修改对象，但风险边界尚不充分。

## 1. Open Math Harness v0.41.0：数学科研 Agent 的能力内核 + Lean 证明检查

- **官方仓库：** https://github.com/openmathmodel/open-math-harness ；**首个公开 Release：** https://github.com/openmathmodel/open-math-harness/releases/tag/v0.41.0 ，发布于 **2026-10-23 04:54 UTC**。GitHub REST **126 Stars / 12 Forks**，创建于 10 月 22 日，Apache-2.0。
- Rust 编写的 Open Math OS 运行时，内含以能力（capability）授予为边界的微内核；Ultramath 让多个 Agent 并行探索不同思路，交换引理、反例与失败路线。证明搜索对固定 Lean 命题开展树状并行搜索，**候选证明以 Lean/Mathlib 检查结果为准，而非模型自述**。
- 项目支持会话记忆、MCP、Shell/PDF/Web 工具及人工批准受保护操作；明确把模型输出、工具返回和仓库内容视为不可信输入。与通用科研 Skills 的“工具说明书”不同，本项目将**权限、探索协作与证明验证**做进运行时。
- **关键限制：** 官方明确完整运行时依赖 Open Math OS 部署环境；当前仓库只能在 Linux/bubblewrap 上构建和运行小型自包含示例，**尚不能独立本地部署交互 Agent 或完整证明搜索**。未独立验证数学正确率和沙箱强度。

## 2. OPAL v0.3.7：训练过程中由 Coding Agent 重写优化器

- **官方仓库：** https://github.com/xingjian-bai/opal ；**Release：** https://github.com/xingjian-bai/opal/releases/tag/v0.3.7 ，发布于 **2026-10-22 22:48 UTC**。GitHub REST **184 Stars / 8 Forks**，创建于 10 月 21 日，MIT。
- OPAL（Optimizer with an Agent in the Loop）通过 `opal.wrap` 包装 PyTorch 优化器，定期由 Coding Agent 分析训练指标，修改**梯度更新程序**与**诊断程序**，可调整学习率、动量、预条件化、裁剪等；支持无模型调用的 `backend="keep"` 基线对照和代码差异/费用报告。
- 技术路线由“模型训练前手工选定优化器”转向 **训练中观测 → Agent 生成更新规则 → 受控执行 → 继续观测**。项目提供跨主机 mailbox 运行 Agent 的设计，强调训练前成本与等待时间估算。
- **关键限制：** README 明确生成的优化器代码**在训练进程内部执行，不构成沙箱**；“不得改动模型/数据/评估”的约束只是提示词规则。v0.3.7 主要是文档和示例更新，**不是优化器算法新发布**。表中 FID/损失结果均为作者报告的单次实验，未独立复现；`blocking="auto"` 被标为实验性。

## 3. VVV v0.1.1：跨 Coding Agent 的可编辑视频模板与交付格式

- **官方仓库：** https://github.com/actionow-ai/vvv ；**Release：** https://github.com/actionow-ai/vvv/releases/tag/v0.1.1 ，发布于 **2026-10-23 10:16 UTC**。GitHub REST **247 Stars / 69 Forks**，创建于 10 月 22 日，MIT。
- 以可重用 Remotion/React/TypeScript 模板为中心：Agent 先通过 `describe` 了解照片槽位、文案和参数，`validate` 校验输入，再渲染样片、运行 `vvv check` 检查格式、音频、静帧与节拍同步；`.vvv` 包打包源码、媒体授权和渲染证据，便于不同 Agent 接力。
- v0.1.1 引入 `vvv.py doctor` 环境诊断与**机器可操作的下一步修复提示**，让安装、渲染失败能够被 Agent 处理。与此前 HyperFrames 的 HTML/CSS 时间轴视频不同，VVV 强调 **模板复用 → 参数化重制 → 自动质检 → 可编辑跨 Agent 交接**。
- **关键限制：** 官方称 macOS ARM64 + Claude Code/Codex 完整链路已验证，其他宿主测试较少；节省 Token 和重建视频质量没有公开独立对照基准。人工审美检查仍不可省略。

## 4. gitai v0.4.0：多 Agent 版本控制的引用解析和服务端权限加固

- **官方仓库：** https://github.com/feder-cr/git-ai ；**Release：** https://github.com/feder-cr/git-ai/releases/tag/v0.4.0 ，发布于 **2026-10-23 09:16 UTC**。GitHub REST **980 Stars / 96 Forks**，License API 返回 `NOASSERTION`（README 自述 MIT，需按 LICENSE 文件核实）。
- 新增仅操作员可用的 `graft repo create` / SDK `Repo.Create`，可重试收敛；**Agent Token 被拒绝创建仓库**。多种 RPC 的分支读取改为精确 `refs/heads/` 语义，避免标签或模糊 revision 冒充分支起点；服务端统一禁止 Agent 写入内部 `refs/graft/`，并关闭对 Agent 的 `SSHUploadArchive` 入口。
- 对比 10 月 21 日 v0.3.0 的并发落地、10 月 23 日 v0.3.1 的剩余冲突错误率，本版重点转为 **服务端最小权限与引用身份不可混淆**。同时将 reftable 并发整理冲突视为可跳过的维护事件，避免误中断后续整理。
- **关键限制：** 若旧配置将 `gitaly.SSHService/SSHUploadArchive` 放入 Agent RPC 白名单，升级后服务器会拒绝启动；错误码亦有不兼容变化。安全修复来自官方实现/测试，未进行独立渗透验证。

## 5. SCP Broker 0.9.0：休眠 Agent 的一次性唤醒票据与身份接管

- **官方仓库：** https://github.com/scphq/scp ；**Release：** https://github.com/scphq/scp/releases/tag/%40scp-dev/broker%400.9.0 ，发布于 **2026-10-23 21:04 UTC（北京时间 10 月 24 日 05:04）**。GitHub REST **69 Stars / 1 Fork**，Apache-2.0。
- 休眠记录包含 `harness/session/cwd/argv/via`；唤醒器每次获得**一次性 wake ticket**，恢复后的会话凭票据重新 claim 原 Endpoint，保留地址、未读消息和组信息；票据耗尽则回退为普通 claim。后台 Claude Code Worker 空闲 600 秒后可停止，符合条件的历史 Worker 可移除，收到消息后恢复。
- 与 10 月 23 日首次收录的 SCP 协议/turn-level 消息不同，本版给出更具体的 **休眠身份 → 一次性票据 → 原 Endpoint 认领 → 邮件/组状态继承**，是跨 Harness 长寿命任务恢复的关键实现点。
- **关键限制：** 官方 README 中“数月后恢复”的说法未独立验证；需故障注入检查重放票据、重复唤醒、断网、权限撤销和原会话上下文完整性。该版本只证明作者实现了相关逻辑，**不能断言 exactly-once**。
