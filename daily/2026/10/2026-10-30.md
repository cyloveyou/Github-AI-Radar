## 1. OpenMausBot：跨模型故障切换 + 每 Bot MCP 隔离

- **官方仓库：** https://github.com/milind-soni/OpenMausBot ，Apache-2.0，**7,458 Stars / 1,112 Forks**；Trending 滚动 **1,199 stars today**，2026-08-11 创建，首次收录。
- **官方 Release：** 10 月 29 日 `v0.1.132` https://github.com/milind-soni/OpenMausBot/releases/tag/v0.1.132 ：额度耗尽时按预先选择的备选模型继续执行例行任务；每个 Bot 自己创建的 MCP Server 只在该 Bot 内启动；读取自己的记忆、技能和会话文件不再要求额外批准。10 月 29 日 `v0.1.133` https://github.com/milind-soni/OpenMausBot/releases/tag/v0.1.133 修复 Windows API-key 模型触发的 128 MCP 工具限制及本地模型超时问题。

## 3. Hydro Infinity：事件驱动、可休眠的高并发 Agent Runtime

- **官方仓库：** https://github.com/hydro-project/infinity ，Apache-2.0，**375 Stars / 35 Forks**；Rust Trending 滚动 **180 stars today**，首次收录。
- **技术路线：** Agent 等待工具或消息时将状态保存为会话数据、释放驻留任务，收到事件再唤醒；Reactive Agent Protocol（RAP）让工具结果在无持续连接时回送，并提供 MCP 桥接与 Lambda 部署路径。官方 README：https://github.com/hydro-project/infinity 。这与常驻进程、线程池式 Agent 并发不同。
- **兼容性提醒：** `sandbox-core-v0.2.0`（10 月 22 日）将 ToolCallId/ProviderCallId 变为不同类型，官方声称序列化线格式不变；文档说明部分示例依赖后续发布。https://github.com/hydro-project/infinity/releases/tag/sandbox-core-v0.2.0 。“树莓派内存容纳 75k Agents”是官方主张，未复现吞吐、P99 延迟或故障恢复。

## 4. OpenViking：记忆、知识和 Skills 统一为可寻址文件系统

- **官方仓库：** https://github.com/volcengine/OpenViking ，AGPL-3.0，**41,150 Stars / 3,336 Forks**；首次收录。以 `viking://` 路径统一知识、长期记忆、Skills，支持按目录检索和 L0/L1/L2 分层摘要，保留可查看/编辑的上下文。官方 README：https://github.com/volcengine/OpenViking 。
- **关键发布：** 10 月 27 日 `v0.5.2.1` **临时关闭新敏感值的 Session 自动识别与替换**，以修复普通内容被错误替换的问题；已登记敏感值的匹配仍保留。https://github.com/volcengine/OpenViking/releases/tag/v0.5.2.1 。这意味着未登记的新秘密不再自动发现/脱敏，**不是“隐私保护全面增强”**。
- **验证重点：** 在真实科研数据、凭据和项目记忆中测试隐私识别的漏报/误报、路径权限、记忆回滚与删除传播。AGPL 的网络服务部署须评估相应许可义务。
