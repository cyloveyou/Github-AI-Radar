- **官方 GitHub REST：** 62,751 Stars / 5,627 Forks；Apache-2.0；2026-03-10 创建。Trending Weekly 本次显示 4,482 stars this week（页面口径，不是两次 REST 快照差值）。

- **机制：** 通过 HTML、CSS、媒体与可寻址动画时间轴定义视频，使用 CLI 渲染 MP4；面向 Claude Code、Codex、Cursor、Gemini CLI 等提供 Agent Skills/插件，README 描述 21 个按需调用的 Skills。

- **局限：** 确定性是项目设计目标，跨字体、FFmpeg 版本和媒体资产的逐帧一致性仍需独立实测。

## 2. claude-mem v13.39.0 — 子 Agent 压缩后的记忆连续性

- **官方仓库：** https://github.com/thedotmack/claude-mem
- **官方 GitHub REST：** 100,431 Stars / 8,799 Forks；Apache-2.0；2025-08-31 创建。Trending Weekly 本次显示 3,762 stars this week。
- **官方发布：** https://github.com/thedotmack/claude-mem/releases/tag/v13.39.0 ，2026-10-13 21:31:41 UTC。
- **重要修复：** Codex 子 Agent 线程在上下文压缩后不会收到根线程的 SessionStart(compact)，可能丢失 memory timeline。新版通过 PostCompact 标记 session_id + agent_id，在该线程下一次 PostToolUse 中以 additionalContext 恢复一次；根线程 SessionStart 清除标记以防重复注入。
- **技术路线：** **线程身份 → 压缩边界 → 事件 hook → 单次记忆恢复**。与 Context Mode 的工具输出路由、Hindsight 的事实/指导治理不同，这解决的是多 Agent 长任务的恢复正确性。
- **局限：** 需要独立验证并发子 Agent、崩溃恢复、标记丢失、重复注入与不同客户端 hook 兼容性。

## 趋势、去重与后续验证

**Agent Skills → 专业源文件成果物 → 可重复执行/渲染 → 验证；Memory Store → per-thread lifecycle hooks → compaction-aware recovery。** HyperFrames 解决时间轴视频成果物，claude-mem 解决子 Agent 记忆连续性，cursor/plugins 提供官方插件声明与分发。既有 REA、Hindsight、Context Mode、OpenRig、diagram-design 和 text-to-cad 的结论不重复作为新发现。

需重点验证：视频跨机器/编解码器版本的渲染一致性；子 Agent 压缩后的 exactly-once 记忆注入；插件 Manifest 的权限、来源与升级治理。Stars/Forks 不代表性能、可靠性或实际采用率。
