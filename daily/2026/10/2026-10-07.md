# GitHub AI Radar — 2026-10-07

> **本期触发：自维护 Skill、可移植 Agent Memory 规范与可重放 Agent 测试框架出现值得追踪的新信号。** 与既有 Radar 的 Skills / Harness / Memory / Browser Agent 记录相比，变化在于「经验写入—治理—跨会话复用—执行验证」开始有具体的生命周期和接口。

## 1. tigerless-labs/autoharness — 自维护 Skill 生命周期

- **官方仓库：** https://github.com/tigerless-labs/autoharness
- **分类：** Coding Agent / Harness / Skills / Self-learning
- **GitHub REST 核验：** 9,181 Stars、601 Forks；MIT；2026-06-09 创建；2026-10-07 仍有更新。
- **机制：** Claude Code 插件通过 hooks 捕获真实工作片段；reflection 提出创建、合并或修订 Skill 的建议，promoter 校验后才写入。每个 Skill 保留证据账本，并按实际使用情况归档；只管理插件自己生成的 Skill，不触碰用户手写 Skill。
- **新意：** 9 月 Radar 已记录 Skills、Harness 与 Git/Markdown Memory，但尚未出现这样完整的在线「生成—去重—审计—退役」闭环。项目明确以真实使用中的复用而非独立 benchmark 作为筛选信号。
- **边界：** README 中的 42%→78% CORE-Bench 数字引用的是外部 Harness 研究，**不是 autoharness 自身的实测性能提升**。

## 2. AgentMemoryRepo/agentmemoryrepo — 跨 Agent 的 Git 记忆规范

- **官方仓库：** https://github.com/AgentMemoryRepo/agentmemoryrepo
- **分类：** Agent Memory / Open Specification / Git-backed Context
- **GitHub REST 核验：** 613 Stars、30 Forks；MIT；2026-10-04 创建。
- **机制：** 独立 Git 仓库存放互链 Markdown、脚本和结构化记录；Agent 可检索、更新、提交，Git 冲突暴露多 Agent 并行编辑问题。官方提供 Devin 及其他 Coding Agent 的 Skill 安装说明。
- **新意：** 与 9 月 22 日已记录的 `akitaonrails/ai-memory` 理念相近，但本次重点是**独立格式规范与跨客户端复用**，而不是某个单一工具的记忆功能。官方 README 表示规范最初由 Cognition 开发。
- **边界：** 仓库很新，广泛互操作性尚待验证；周期性 Dreaming 是规范描述，示例安装并不自动提供定时 Dreaming。

## 3. tester-army/e2e — Agent 探索、确定性断言与重放

- **官方仓库：** https://github.com/tester-army/e2e
- **分类：** AI Testing / Browser & Mobile / Coding Agent Tools
- **GitHub REST 核验：** 7,437 Stars、338 Forks；Apache-2.0；2026-07-22 创建，持续开发。
- **机制：** 自然语言描述任务，Agent 驱动 Web/Mobile 应用到达目标，再以定位器和断言检验结果。已验证的 Agent 动作可在后续运行中重放，直到界面变化，减少重复模型调用。
- **新意：** 从「Agent 会操作浏览器」推进到「探索动作可固化为可重复、可断言、可进入 CI 的测试资产」，与此前 BrowserSkill / CUA 的执行能力互补。
- **边界：** 官方明确仍在走向 1.0，API 可能变化；不将 Star 增长等同于生产稳定性。

## 4. CopilotKit/OpenDots — 持久 Agent 工作空间（次级信号）

- **官方仓库：** https://github.com/CopilotKit/OpenDots
- **GitHub REST 核验：** 4,195 Stars、581 Forks；MIT；2026-09-29 创建。
- **机制：** 每个 Dot 可配置独立持久计算机、浏览器/文件、MCP 权限、人类审批及原会话内后台任务。官方强调这是早期**可自部署模板**，不是已托管完整产品。
- **去重：** Radar 已记录 `CopilotKit/openmuse`；OpenDots 官方承认借鉴 OpenMuse / OpenBot，因此视为「persistent agent coworker」路线的延展，而不是全新范式。
- **限制：** 对话需要配置 CopilotKit Intelligence；本地模板不意味着所有功能默认离线可用。

## 结构性判断

```text
Real sessions -> Skill distillation / merge / audit / retirement (autoharness)
             -> Git-linked portable memory / multi-agent coordination (Agent Memory Repo)
Agent actions -> deterministic assertions -> replay / CI (e2e)
             -> persistent per-agent computer + approval (OpenDots, secondary)
```

此前 Radar 的 Sandbox / Runtime / Control Plane 解决「在哪里执行、由谁授权」。本期补充「Agent 学到的经验如何不失控地积累，以及完成的动作如何可靠复验」。两条路线互补，不应把热度等同于工程质量。

后续应量化：Skill 真实复用率、合并/归档误判率、跨 Harness 记忆可移植性、Agent 测试重放命中率和 CI 稳定性。
