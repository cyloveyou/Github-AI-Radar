# GitHub AI Radar — 2026-09-29

> 今日触发更新：NVIDIA 在 9 月 28 日正式发布 Open Agent Safety Platform，并把 OpenShell 推到“Agent 外部可强制执行的安全 Runtime”核心位置。它不是新的 Agent Framework，而是把前一期 Radar 记录的 Sandbox / Runtime / Portable Authority 主线进一步推进到 **Runtime Enforcement + Formal Policy Verification + Out-of-band Hardware Watchdog**。这属于显著技术路线变化，因此触发日报。

## NVIDIA / OpenShell

- **Repo:** https://github.com/NVIDIA/OpenShell
- **Category:** Agent Runtime / Sandbox / Runtime Policy Enforcement / Agent Safety
- **Verified snapshot:** 本次 GitHub REST 核验为 9,397 Stars、1,334 Forks；Apache-2.0；仓库创建于 2026-02-24，扫描时仍有最新提交。
- **What:** OpenShell 为自主 Agent 提供独立 sandbox，并在内核层对文件访问、system call 和网络连接执行策略；真实凭据不直接暴露给 Agent，而是在获准请求发往批准端点时注入。
- **Policy model:** 官方仓库明确说明，策略变更在应用前可进行形式化验证，用于识别新增主机访问、携带凭据访问新端点或新增 API 方法等风险，再等待人工审查。
- **Why watch:** Agent 安全边界正从 prompt / harness 内部约束转移到 Agent 无法自行绕过的外部 Runtime Enforcement。

## NVIDIA Open Agent Safety Platform — 从软件 Sandbox 到独立监督平面

NVIDIA 2026-09-28 官方公告把 OpenShell 与 Sentry 组合成 Open Agent Safety Platform：

- **OpenShell:** 软件侧 secure runtime boundary，追踪 Agent 动作并执行策略；
- **Sentry:** 参考系统设计中的 out-of-band watchdog，运行于 BlueField-4 DPU，在与 Agent/宿主执行路径隔离的信任域中持续监控；
- **Full-stack control:** 控制范围从模型/应用层延伸到软件、计算基础设施与机器人执行层；
- **Interoperability:** OpenShell 是开源软件，NVIDIA 表示可扩展到 Arm、Intel 等第三方计算平台；
- **Ecosystem signal:** NVIDIA 官方列出 Anthropic、Microsoft、SAP、Salesforce、Hugging Face、Red Hat、Cisco、CrowdStrike、Palantir、Perplexity、ServiceNow、Scale AI 等大量参与方。

这里真正值得 Radar 记录的变化不是“又一个安全项目”，而是安全控制的责任边界发生迁移：

**Agent 自我约束 → Harness Guardrails → Sandbox Isolation → Runtime Policy Enforcement → Independent Watchdog / Hardware Trust Domain**

## 与 2026-09-26 Radar 的关系

9 月 26 日记录的 Docker Sandbox Kit v3 强调 **Portable Authority / OCI Packaging**：把 Agent、工具与权限策略一起版本化和分发。

本期 OpenShell / Sentry 则补上另一侧：**运行时权限必须由 Agent 外部的执行层强制落实，并且高风险场景进一步引入独立监督平面。**

两条路线正在汇合为：

**Agent + Tools + Declared Authority + Isolated Runtime + Enforced Policy + Auditable Telemetry + Independent Oversight**

因此，Sandbox 已不只是“防止 Agent 把机器弄坏”的容器，而正在成为 Agent 时代的权限边界、审计边界和部署边界。

## 对科研工作流的直接启发

1. 高权限科研 Agent 的安全设计应从“提示词告诉它不要做什么”转向“运行时根本不允许它做什么”；
2. 数据下载、批处理、绘图、远程服务器操作等长任务可把网络域名、目录、凭据与系统调用权限显式化；
3. 对 NAS、多服务器、实验数据与投稿材料，凭据应由受控执行层按批准端点注入，而不是直接暴露给 Agent；
4. 后续重点跟踪 OpenShell policy、Docker Sandbox Kit/OCI authority 与其他 sandbox protocol 是否出现互操作或事实标准。
