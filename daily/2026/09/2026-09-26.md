# GitHub AI Radar — 2026-09-26

> 今日触发原因不是单一“高 Star 新仓库”，而是 **Agent Sandbox 正从一个安全功能升级为可打包、可迁移、可在本地/云端一致执行的基础设施标准**。Docker 在 9 月 24–25 日公开 Cloud Sandboxes 与 Sandbox Kit Specification v3，这与此前 Radar 连续观察到的 Runtime / Control Plane / Sandbox 主线形成明显二次确认。

## Docker / sandbox-kit-spec

- **Repo:** https://github.com/docker/sandbox-kit-spec
- **Category:** Agent Sandbox / Packaging Standard / Authority-as-Code
- **Verified snapshot:** 2026-09-26 约 62 Stars、6 Forks；仓库创建于 2026-09-16，9 月 25 日仍有提交。
- **What:** Docker Sandbox Kit Specification v3 将 Agent、工具以及它被允许访问的网络、凭据、卷等权限声明封装为 OCI artifact，并提供 BuildKit frontend 与 conformance suites。
- **Why watch:** 这不是普通 Agent Framework。关键变化是把 Agent 的“执行权限”变成可版本化、可签名、可扫描、可分发的 artifact 属性，接近 **authority as code**。
- **Primary evidence:** Docker 2026-09-24 官方公告明确说明 Kit v3 以 OCI image 为载体，并以 Apache 2.0 开源，计划向 CNCF 推进中立治理。
- **Workflow value:** 对科研 Agent 尤其有意义：下载器、处理脚本、绘图 Agent 可以连同允许访问的数据目录、网络域名、凭据范围一起版本化，降低高权限自动化失控风险。

## Docker / sbx-releases — Cloud Sandboxes + v3 Kits

- **Repo:** https://github.com/docker/sbx-releases
- **Category:** Agent Sandbox / Cloud Runtime
- **Verified snapshot:** 约 405 Stars、22 Forks；v0.45.0 发布于 2026-09-21。
- **What changed:** v0.45.0 支持 v3 OCI Kits 的组合式环境；Docker 随后在 9 月 24 日宣布 Cloud Sandboxes，可将相同的 microVM 隔离模型从本机延伸到 Docker 托管云端。
- **Why watch:** Agent 长任务开始要求“关掉笔记本仍继续跑”，因此 Sandbox 正与 Runtime 融合。Docker 官方将其描述为 harness-neutral、model-neutral 的隔离执行环境。
- **Trend:** 这与此前 google/ax、Nasiko-Labs/nasiko、coder/coder 的 Runtime / Control Plane 信号形成二次爆发：**隔离执行 + 可移植权限 + 云端长任务** 正在汇合。

## opensandbox-group / OpenSandbox

- **Repo:** https://github.com/opensandbox-group/OpenSandbox
- **Category:** Agent Sandbox Runtime / Open Protocol
- **Verified snapshot:** 约 15.5k Stars、1.4k Forks；2026-09-25 仍有提交。
- **What:** 为 Coding Agent、GUI Agent、Agent Evaluation、AI Code Execution 与 RL Training 提供统一 Sandbox API，覆盖 Docker/Kubernetes runtime，并提供 Python、Java/Kotlin、TypeScript、C#/.NET、Go SDK、CLI 与 MCP。
- **Why watch:** 它说明 Sandbox 正从“某个 Agent 的内部实现”抽离成独立平台层，并开始强调公开协议和从 laptop 到 cluster 的统一 API。
- **Caution:** 今日把它作为生态结构性佐证，而不是声称它在过去 24 小时新增了某个未经验证的 Star 增速。

## microsoft / quicksand

- **Repo:** https://github.com/microsoft/quicksand
- **Category:** Agent Sandbox / QEMU VM
- **Verified snapshot:** 约 53 Stars、7 Forks；2026-09-24/25 仍活跃。
- **What:** 面向 AI Agent 的异步 Python VM sandbox API，基于 QEMU，支持 Ubuntu/Alpine、x86_64/ARM64，强调无需 root 或 Docker。
- **Why watch:** 与 Docker microVM 路线并行，说明“给 Agent 独立内核/VM 边界”正在成为更明确的工程选择，而不是只依赖普通容器隔离。

## 今日判断

本期最重要的不是 Star 榜单，而是基础设施层的结构性变化：

**Agent Framework → Harness → Sandbox → Runtime → Portable Authority / OCI Packaging → Cloud Execution**

相比 9 月 23 日 Radar 观察到的 Runtime / Control Plane，本期新增的一层是 **可移植权限与打包标准**。如果这一方向继续扩散，未来 Agent 的可复现部署单位可能不只是 Dockerfile 或 Skill，而是“Agent + Tools + Permissions + Secrets policy + Network policy”的可签名 artifact。

## 对科研工作流的直接启发

1. 高权限科研 Agent 不应直接继承宿主机全部环境，优先把目录、网络与凭据权限显式声明；
2. 长时间下载、预处理、批处理和绘图任务适合迁移到可恢复的 sandbox/runtime，而不是依赖聊天会话或本地终端常驻；
3. 可复现实验环境未来可以从“代码 + Conda/Docker”进一步升级为“代码 + Agent + 工具 + 权限策略”；
4. 对多服务器科研环境，值得继续跟踪 OCI Kit / Sandbox Protocol 是否形成跨运行时互操作标准。
